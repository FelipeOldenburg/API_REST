# Issue tracker: GitHub

Issues e especificações deste repositório vivem no GitHub Issues. Use `gh` para criar, ler, listar, comentar, rotular e fechar issues.

- PRs como superfície de triagem: não.
- Quando uma skill pedir para publicar tickets, crie GitHub Issues.
- Quando uma skill pedir um ticket, use `gh issue view <número> --comments`.
- Dependências entre tickets usam as dependências nativas do GitHub; na indisponibilidade, use `Blocked by: #<número>`.
